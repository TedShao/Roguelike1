日期：2026-10-26。这里是未来开发的进入条件和验证计划，**不是启动开发的授权，也不是已经通过的测试报告**。任务进度只维护在 [roadmap](../roadmap.md)。

## 2. 技术与目标平台提议

已核验的事实：本机 Godot 4.7.2 可返回版本号，默认导出模板目录为空；没有图形项目、导出或性能验证，见[环境评审](../development-readiness-review.md)。

建议技术基线为 Godot 4.7.2、GDScript、2D Compatibility；地图表现先俯视正交 2D 格盘，人物可用侧面／四向精灵，但逻辑不依赖画法。该建议尚未锁定引擎或最终镜头；以后采用等距绘制也必须保留同一可读的四邻逻辑。

拟先验证当前 macOS 开发机和 Windows 11 桌面导出，Steam 发行首发系统仍需决定。当前没有已确认的 Windows 测试机、GPU／内存最低配置、分辨率覆盖结果，不能写成已支持。首版界面以 1280×720 至 1920×1080 窗口区间为设计检查点，允许缩放；性能目标待代表性素材实测后制定，不预先保证 60 FPS。

需要在对应阶段补齐：锁定引擎／脚本／渲染方案、目标系统、代表性设备；安装匹配版本的导出模板；实际新建空工程验证导入、输入、保存与打包。工具安装和模板缺失不妨碍当前设计工作，本轮不执行这些工程动作。

## 3. 首版美术与声音生产需求

采用功能占位先验证，再做统一画风；占位也须能读懂单位、格子和预告。2D 资源可用性仍未完成检索，不能因为选择 2D 就宣称资产已经齐备。

|类别|最小需求与验收|
|---|---|
|玩家|1 中性白板轮廓；待机、移动、近战、远程施放、防护、受击、死亡 7 类状态；近战／施法靠姿态和效果区分，不把外观锁成职业|
|普通怪|3 可区分轮廓；跟风者追击／攻击，抬杠者蓄力／重击／恢复，传话筒蓄力／施压／恢复；统一受击／死亡反馈|
|首领|1 锚定主教轮廓，预告、执行、召唤、恢复、死亡状态；召唤位置独立标记|
|NPC|3 头像或站立图，服务入口图标；不为首次版本制作大量对话演出|
|场景|一套地面、实墙、边界、出生／出口标记；4 张地图复用；碰撞格与美术墙一致|
|图标与效果|10 技能、8 符文、3 遗物及系统图标；物理命中、魔法命中、碰撞、爆炸、屏障、施压、透支、超载、预告，允许复用且保留来源辨识|
|UI|生命、屏障、压力、计时器、库存卡、精修选择、商店、事件、结果；长中文名称和数字增长不截断关键信息|
|声音|选中／取消／确认、命中、死亡、防护、预告、透支／超载、奖励、交易等功能组；音乐先一段可循环氛围，音效／音乐分别可调|

正式资产必须记录来源、许可证／商业使用范围、修改要求、署名、可编辑源与导出规格。当前没有已选素材，也没有制作预算和工时确认；不批量采购或生成。视觉先比较同一场景中“荒诞语义＋压迫环境”的表达，不照搬现有游戏角色或中文社区人物肖像。幽默不应遮盖技能真实功能。

## 6. 体验验收与不通过时的处理

试玩先观察四种意图：近战法师、肉盾刺客、物法协作、推击核心。相同成长预算、指定相同奖励条件进行对照，但不把试玩者锁进“职业”。至少包含一次缺少图鉴示例符文的局面，观察能否使用基础替代；询问其理解，不能以通关代替理解。

重点记录：何时开透支、是否理解后两回合承伤、是否专门绕圈等 5 回合、每房整理耗时、商店补强与治疗选择、战败能否解释、是否愿意尝试新组合。短房目标看实际行动数和整理比例；没有测量就不报告达标。

若透支总是开局必按，先检查预告空窗和敌人覆盖；若总是等冷却，优先评审跨房冷却及房间节奏；若玩家只追同一技能，检查替代技能是否真有用；若免费重配让每房都像做题，先改建议展示和操作成本，不未经讨论收回已确认的免费重配。规则正确、运行稳定和好玩分别记录，不能相互替代。
