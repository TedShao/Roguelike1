## 目前可以带入讨论的判断

**1. 不应由销量选战斗形式。**回合决策、完整动作与自动攻击均有大规模成功样本，但这些项目的内容、发行、价格与生命周期不同，不能推出我们采用某种形式也会成功。中文评价与全球热度也不应混为同一指标。[市场证据](market.md)

**2. 未成型阶段不能只剩等核心。**土豆兄弟开发者强调多数组件独立可用；杀戮尖塔玩家描述理解过渡牌的过程；魔法工艺及枪火重生样本中出现核心依赖、早期阶段无趣的反馈。由此提出的假设是“先能用，再组合得更好”，同时保留“基础能力过强会使组合无意义”的反例。[机制与玩家证据](mechanism-dossiers.md)

**3. 碾压和持续挑战不是一件事。**有人希望保留强组合的展示，有人认为成型后的长局变成等待。我们需要决定是给予短暂的胜利展示、继续创造新选择，还是服务喜欢长时间自动清场的人群；不能替所有玩家下结论。[跨作品发现 C3](comparison.md#c3成型后的碾压需要一个合适的结束点)

**4. 构筑可解释性本身就是产品能力。**同样是满屏效果，玩家能否说清是谁触发了谁，会影响下次奖励能否形成有依据的选择。增加技能、符文和装备层次之前，应先确认每层创造了新的决定。[迁移清单](transfer-checklist.md)

## 如何使用这份研究

已选择逐回合控制位置、目标与技能的方向；已确定“单角色”“一步一响应”“关键预告”与“局内自由构筑”，接下来讨论构筑组件分工、单局节奏、失败代价与奖励纠偏，随后再定画风、镜头和技术。当前材料足以支持带证据的取舍讨论，不足以给出已验证的乐趣结论。

中文评价采用目的抽样，推荐和不推荐配额相同，**不能用于估计全体玩家意见比例**。历史文本与当前版本逐项区分；长时长、好评按钮和文字内容也不被自动视为一致。

影像只做了局部官方展示核查，没有观看十款完整流程、亲自试玩或测量完整局长。关于首次联动时间、最佳奖励密度、真正操作压力、性能及留存效果均保持待验证。研究阶段没有编写游戏代码或制作原型；随后按用户要求创建 [GitHub 仓库](https://github.com/TedShao/Roguelike1) 并将文档纳入 Git 管理。
